# ADR 0001: TypeScriptモノレポとして初期化する

## ステータス

採用

## 背景

短期間のチーム開発で、金融スマートフォンアプリケーションのフロントエンドとバックエンドを並行して実装する。空のリポジトリから、品質検証と責務分離を備えた初期構成が必要だった。

## 課題

- 参加者が短時間で開発を開始できること
- フロントエンドとバックエンドの責務を混在させないこと
- 型、フォーマット、lint、テスト、ビルドをPull Requestごとに検証できること
- 小規模な初期段階で過剰な構成にしないこと

## 選択肢

1. React/ViteとExpressをnpm workspacesで管理する
2. Next.jsに画面とAPIを集約する
3. フロントエンドとバックエンドを別リポジトリにする

## 採用した案

React/ViteとExpressを`frontend`、`backend`に分け、npm workspacesで一元管理する。

## 採用理由

- TypeScriptを両方で利用でき、型に関する学習内容を共有しやすい
- 各アプリの責務を明確にしながら、依存導入と品質チェックをルートから実行できる
- ViteとExpressは構成が小さく、短期間でも仕組みを理解しやすい
- 将来DBや外部APIを追加しても、バックエンド側の境界内に隔離できる

## メリット

- 1回の`npm ci`で開発環境を再現できる
- CIの検証方法をローカルと統一できる
- フロントエンドとバックエンドを独立して起動・テストできる
- 依存更新を1つのlockfileで管理できる

## デメリット

- 片方だけを扱う開発者もリポジトリ全体を取得する必要がある
- Expressはルーティングやエラー処理などの設計をチームで決める必要がある
- SSRやサーバーレス運用は初期構成に含まれない

## 将来的な見直し条件

- SSRやBFFの必要性が明確になったとき
- workspace間で共有する型やパッケージが増え、専用の共有packageが必要になったとき
- API規模の拡大により、OpenAPI生成やより構造化されたフレームワークが必要になったとき
- デプロイ単位を完全に分離する運用要件が発生したとき
